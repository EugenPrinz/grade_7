# degasser — CHANGELOG

## install.lua — 2026-10-31
Установщик и обновлятор.
- **Установка:** `degasser.lua` → `/home/bin`, конфиг → `/home`.
  - Если конфиг уже есть, он не трогается; свежий шаблон кладётся в `.new`.
  - `--force-config` перезаписывает конфиг, старый сохраняется в `.bak`.
- **Флаги:** `--autostart` добавляет запуск в `/home/.shrc` (без дублей), `--ref` ставит из другой ветки, тега или коммита.
- **Защита от битых загрузок:**
  - скачанное должно компилироваться;
  - в конце файла обязателен маркер `-- END <имя>`. Добавлен в `degasser.lua` и `degasser.cfg.lua`, потому что тест показал: оборванная на границе строки загрузка компилируется;
  - запись атомарная (`.tmp` → rename).
- **Тесты:** `test/install_test.lua`, 13 проверок, все ok.

## 1.2.0 — 2026-10-31
Поддержка ME Dual Interface как источников: компактная сборка у хэтча, AE доливает жидкость по беспроводной сети. Transposer'ы UV.

- **`refillSources = true`** (глобально или `routes.X.refill`). Источник считается доливаемым: его содержимое может быть меньше одной подачи.
- **Предпроверка `available()`:**
  - есть ME-компонент → содержимое интерфейса + запас сети (`getFluidsInNetwork()`, кэш 3 с);
  - нет ME-компонента → «интерфейс заполнен ≥90% ⇒ AE дольёт». В этом режиме возможна частичная подача, если сеть пуста; при старте выводится предупреждение.
  - без `refill` поведение прежнее: содержимое буфера ≥ нужного.
- **`me`:** адрес Adapter'а у любого ME-блока. nil = автопоиск единственного (`me_interface` / `me_controller` / `me_dual_interface`), false = не использовать. Если у компонента нет `getFluidsInNetwork`, программа предупреждает и работает без данных сети.
- **Перекачка:** `stallTimeout` (по умолчанию 15 с) — если поступления нет, подача прерывается и выполняется откат. Раньше висела до дедлайна цикла.
- **Экран буферов:** показывает запас сети (`сеть`) или заполненность интерфейса (`AE доливает · сеть ?`), без ложного «ПУСТО».
- **`scan`:** выводит ME-компоненты и число жидкостей в сети.
- **README:** схема подключения под Dual Interface, установка через wget, диагностика.
- **Тесты:** сценарии `iface` / `iface-nome` / `iface-dry` (интерфейс 8000 L, долив 4000 L / 5 тиков).
  - `iface` и `iface-nome`: 100% успеха, 10 000 L coolant/He подаются через долив.
  - `iface-dry`: 65 циклов пропущено по нехватке, **0 частичных подач**.
  - Старые сценарии без изменений.
- **Открытый вопрос:** точная ёмкость танка Dual Interface и наличие `getFluidsInNetwork` в твоей версии AE2 — смотреть через `degasser scan`.

## 1.1.0 — 2026-10-31
Экран статуса для GPU и монитора T3 (160×50), только отображение, и шанс на выход.

- **Экран** перерисовывается по `event.timer` каждые `uiInterval` секунд, независимо от логики подачи. Блоки рисуются заново только при изменении (memo), цвета ставятся только при смене.
  - Прогресс цикла, фаза, тики и секунды до конца.
  - 4 бита сигнала плашками.
  - Подача по каждой жидкости: полоса, залито/нужно, статус.
  - Буферы: на сколько срабатываний хватит, предупреждения.
  - Статистика сессии и последние 20 событий.
- **Шанс на выход:**
  - Крупные цифры, live из `getSensorInformation()` машины. В Degasser `calculateFinalSuccessChance()` пересчитывается по уже слитым жидкостям. Рядом показан прогноз программы.
  - Множитель цикла и параллели тоже из сканера. Ожидаемый объём G7 = параллели × `outputPerParallel` × множитель.
  - Средний множитель для тира SC: 1 + 0.4·(m−1).
  - Тир SC определяется по имени жидкости (`superconductor{uv,uhv,uev,uiv,umv}base`).
- **Подтверждение машиной:** за `guardTicks` до конца цикла шанс читается и записывается как реальный исход цикла. Ведётся статистика «подтверждено ✓/✗» и фактический средний множитель.
- **Парсинг сканера** работает и с переведёнными строками, и с сырыми ключами `GT5U.infodata.*`: берётся последнее число в строке, `1,024` распознаётся как 1024.
- **Фолбэк:** без GPU, при экране меньше 160×50 или при `ui = false` программа работает как 1.0.0, текстовым логом. Если рендер упал, экран отключается и логика продолжает работать.
- **Конфиг:** добавлены `ui`, `uiInterval`, `outputPerParallel` (по умолчанию nil, значение брать из NEI).
- **Проверка (симуляция с моками GPU и таймера):**
  - Сценарии normal / rawkeys / smallhatch / midstart / lowstock / t2screen: рендер без ошибок и без выхода за 160×50.
  - Подтверждённый средний множитель ×1.193 (ожидание ×1.20 для UEV).
  - Мутант с переливом Ne: машина фиксирует 24 провала из 24.

## 1.0.0 — 2026-10-31
Первая версия OC-контроллера Residual Decontaminant Degasser (GTNH, Grade 7).

**Источник механики:** `MTEPurificationUnitDegasser.java` (GT5-Unofficial, master), не вики.
- Сигнал: младшие 3 бита ~ U(0..7), +8 с P=1/5. Выставляется на Control Hatch в `startCycle()`.
- 0 → 10000 L Super Coolant. Бит 3 → ничего. Бит 0 → газ по битам 1-2 (He 10000 / Ne 7500 / Kr 5000 / Xe 2500). Бит 1 → 1440 L SC base (UV..UMV, множитель 1.0..2.0). Бит 2 → 4608 L Neutronium.
- Проверка `amount ==` (точно). Любая лишняя валидная жидкость → 0%. Слив хэтчей каждые 20 тиков, только пока машина работает.

**Решения:**
- Подача: transposer + буферный танк на каждую жидкость (выбор пользователя). AE fake-patterns не используются.
- Новый цикл определяется по сбросу `getWorkProgress()` (adapter на контроллере). Сигнал читается с Redstone I/O (одинаковые сигналы подряд бывают).
- Pre-check запасов: если не хватает, не льётся ничего (провал без потерь).
- Перекачка циклом до точного остатка. Если `transferFluid` не вернул число, программа прерывается.
- Guard за `guardTicks` до конца цикла и откат остатков в буфер. Откат только если в хэтче одна жидкость.
- Старт посреди цикла → ждём следующий.
- `degasser scan` выводит адреса, стороны и имена жидкостей.

**Проверка:** симуляция (texlua 5.3, моки OC + модель по исходнику GT).
- Сценарии normal / smallhatch (2000 L) / midstart / noise: 100% успешных циклов на 400–1000 циклах.
- Мутанты (перелив Ne, игнор бита 3) ловятся симулятором.
- Средний расход совпал с расчётом.

**Известные допущения:**
- Длина цикла 120 с (берётся из машины, не захардкожена).
- Лимит transposer'а за вызов зависит от тира (GTNH 2.8+). Программа работает с любым, медленный transposer просто дольше качает.
- Пользователь сообщил: нейтроний не ограничение (30–100k/день пассивно).
