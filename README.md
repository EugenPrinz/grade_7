# Waterline G7/G8 — OpenComputers (GTNH 2.9)

`WaterLineProgram` запускает G7 и G8 на **одном компьютере или сервере** и даёт общий экран для управления модулями и привязки компонентов. **G7** автоматизирует Residual Decontaminant Degasser: читает сигнал Control Hatch и заливает точные объёмы. **G8** автоматизирует Absolute Baryonic Perfection: по одному вводит кварковые катализаторы до подтверждения правильной пары. G1–G6 можно будет добавить как отдельные модули позже.

Для общего экрана и окна привязки нужны **GPU T3 и монитор T3 с разрешением 160×50**. Без них автоматизация может работать в текстовом режиме, но экранная привязка не откроется.

Механика сверена с [исходником G7](https://github.com/GTNewHorizons/GT5-Unofficial/blob/5.09.54.265/src/main/java/gregtech/common/tileentities/machines/multi/purification/MTEPurificationUnitDegasser.java) и [исходником G8](https://github.com/GTNewHorizons/GT5-Unofficial/blob/5.09.54.265/src/main/java/gregtech/common/tileentities/machines/multi/purification/MTEPurificationUnitBaryonicPerfection.java) из GT5-Unofficial 5.09.54.265, входящего в GTNH 2.9. Подробности — в [CHANGELOG.md](CHANGELOG.md).

| Сигнал | Вероятность | Залить |
|---|---|---|
| 0 | 10% | 10 000 L Super Coolant |
| 1 / 3 / 5 / 7, бит 1 | — | газ по битам 2–3: He 10 000 / Ne 7 500 / Kr 5 000 / Xe 2 500 L |
| бит 2 | 50% от циклов без бита 4 | 1 440 L SC base, множитель выхода UV×1.0 … UMV×2.0 |
| бит 3 | 50% от циклов без бита 4 | 4 608 L Molten Neutronium |
| 8–15, бит 4 | 20% | **ничего** |

Количество должно совпасть **точно**. Любая лишняя жидкость из этого списка даёт провал (0%).

В 2.9 внутреннее имя UV SC base изменилось на `molten.superconductoruvbase`. Скрипт берёт имя из буфера; старый конфиг с `molten.longasssuperconductornameforuvwire` тоже автоматически сопоставляется с новым именем того же тира.

## Железо G7

| Что | Кол-во | Куда |
|---|---|---|
| Computer Case T2+/T3, CPU T2+, 2× RAM T2+, HDD с OpenOS, клавиатура | 1 | куда угодно, кабель OC |
| GPU T3 + Screen T3 (нужно разрешение 160×50) | 1 | к компьютеру |
| Adapter | 1 | вплотную к **контроллеру** Degasser |
| Redstone I/O | 1 | вплотную к **лицевой грани** Degasser Control Hatch |
| Transposer, **UV** (в GTNH 2.8+ нужен тир не ниже LuV) | 2 | вплотную к input hatch'ам катализаторов |
| Input Hatch под катализаторы (отдельно от G6-воды) | 2 | на корпусе Degasser |
| **ME Dual Interface** | 7 | вокруг transposer'ов, по одному на жидкость |
| Adapter для ME (необязательно, но рекомендую) | 1 | вплотную к **любому** из этих Dual Interface |
| Кабель OC | — | компьютер, оба Adapter, Redstone I/O, оба transposer'а (длина любая) |

## Сборка у хэтча

```
 Transposer A (вид сверху)                Transposer B (вид сверху)
           [DI: Coolant]                            [DI: Xenon]
                 N                                       N
 [DI: Krypton] W [TA] E [DI: Neon]    [Adapter ME] ─ W [TB] E [DI: Neutronium]
                 S                                       S
           [DI: Helium]                             [DI: SC base]
   UP   = Input Hatch #1                  UP   = Input Hatch #2
   DOWN = кабель OC                       DOWN = кабель OC
```
*DI = ME Dual Interface. Adapter для ME ставится вплотную к любому DI своей гранью, на схеме он условно показан слева от TB.*

Правила:
- **В каждом Dual Interface ровно одна жидкость в конфиге, без патернов.** Если программа увидит в интерфейсе две жидкости, она откажется из него качать.
- **Dual Interface не касается хэтча Degasser'а**, только своего transposer'а.
- **SC base — один тир.** Два разных тира в одном цикле дают провал.
- В хэтчи катализаторов не идёт ничего, кроме transposer'ов. G6-вода подаётся в третий, отдельный хэтч.
- Хэтч касается transposer'а лицевой гранью.
- Стороны можно выбрать любые: `degasser scan` их покажет. Если повторить схему, в конфиге поменяются только адреса.

Интерфейс может держать меньше, чем нужно за одну подачу: например 10 000 L coolant при ёмкости танка интерфейса меньше этого. Программа качает порциями, пока AE доливает. Если поступления нет `stallTimeout` секунд, подача прерывается и откатывается.

## Установка

1. Поставь OpenOS (`install` с дискеты) и вставь Internet Card.
2. Установщик:
   ```
   wget -f https://raw.githubusercontent.com/EugenPrinz/grade_7/main/install.lua /tmp/install.lua
   /tmp/install.lua --autostart
   ```
   - Установщик ставит `WaterLineProgram`, совместимые отдельные команды `degasser` и `grade8`, модули в `/home/lib/waterline` и три конфига в `/home`.
   - `--autostart` добавляет `WaterLineProgram` в `/home/.shrc`. Старую строку `degasser` он заменяет, сохраняя прежний `.shrc.bak`.
   - **Обновление:** запусти установщик ещё раз. Код обновится, конфиги и файлы привязок останутся; свежие шаблоны появятся с суффиксом `.new`.
   - `--force-config` перезаписывает конфиг, старый сохраняется как `.bak`. `--ref=<ветка|тег|коммит>` ставит не из `main`.
   - Скачанные файлы проверяются: они должны компилироваться и заканчиваться маркером `-- END <имя>`. Пишутся атомарно. Поэтому 404 или оборванная загрузка не испортят рабочую установку.

   Репозиторий должен быть публичным, иначе raw-ссылки не откроются.
3. Запусти `WaterLineProgram bind g7`. На экране выбери контроллер, Redstone I/O, сторону сигнала, ME-компонент и каждый маршрут. Для маршрута выбери transposer, сторону источника и сторону input hatch. Нажми **«СОХРАНИТЬ ПРИВЯЗКИ»**. Сохранённые адреса лежат в `/home/degasser.bindings.lua` и имеют приоритет над основным конфигом.
   - На общей панели выбери G7 клавишей **1** или кликом и нажми **B** для привязки. Модуль дождётся безопасной точки цикла, экран откроется, затем модуль перезапустится.
   - Отдельная команда `degasser` сохранена для совместимости; на её панели тоже есть кнопка **«ПРИВЯЗКА»**.
   - `degasser scan` показывает подробные данные, если нужно проверить компоненты и стороны вручную.
   - Поле `outputPerParallel` для строки прогноза выхода всё ещё задаётся в конфиге по NEI.
4. Запусти `WaterLineProgram`. G7 включён по умолчанию, G8 выключен до постройки. На общей панели **Space** включает/выключает выбранный grade, **B** открывает его привязки, **P** задаёт основу для плана параллелей, **Q** завершает программу после безопасной точки. Выбор модулей и план сохраняются в `/home/waterline.state.lua`.

### Ручная настройка G7

Если экран недоступен, запусти `degasser scan` и заполни конфиг:
   - **gt_machine.** Degasser узнаётся по строкам *control signal* и *Bit*. Его адрес → `machine`.
   - **redstone.** Адрес → `redstone`. Дождись цикла с ненулевым сигналом: сторона с числом 1–15 → `redstoneSide`.
   - **ME.** Адрес → `me`. Нужно, чтобы был виден запас сети; в выводе должно быть «жидкостей в сети: N».
   - **transposer.** Стороны с жидкостями → `from`, пустая сторона с ёмкостью хэтча → `to`.
   - **outputPerParallel.** Выход G7 на 1 параллель из NEI.

## Grade 8

G8 использует **шесть предметных** катализаторов (Up, Down, Strange, Charm, Bottom, Top), input bus и отдельный input hatch с Molten Infinity. Правильная неупорядоченная пара выбирается машиной заново каждый цикл. Скрипт подаёт катализаторы по одному и ждёт, пока каждый появится в истории сенсора; после `Yes` подача прекращается.

Для полного покрытия всех 15 пар нужно не больше 18 вводов (по три катализатора каждого вида). В худшем случае машина расходует 42 слитка Molten Infinity, то есть 6048 L, из-за удвоения стоимости повторов. Необходимый запас воды G7 и обычные хэтчи/выходы обеспечь по рецепту NEI; input bus для катализаторов не должен быть stocking bus.

Поставь Adapter у контроллера G8 и подключи к компьютеру transposer'ы, имеющие доступ к источникам всех шести катализаторов и input bus машины. После сборки:

1. Выполни `grade8 scan`, чтобы увидеть контроллеры, стороны, слоты и предметы.
2. Выполни `WaterLineProgram bind g8`. На экране выбери контроллер и для каждого катализатора transposer, сторону источника, **слот** и сторону input bus. Привязки сохраняются в `/home/grade8.bindings.lua`.
3. В `WaterLineProgram` выбери G8 клавишей **2** и включи **Space**. Скрипт проверяет ID предмета и damage слота, поэтому переводы названий не влияют на подачу.

G8 пока проверен симуляцией: пользовательская конструкция ещё не собрана, поэтому адреса в шаблоне пустые и реальный цикл в мире не проверен.

## План параллелей

Рецепты GTNH 2.9 берут 1000 L воды предыдущего grade и дают 900 L следующего на параллель. Поэтому нижней ступени нужно минимум `ceil(верхние × 1000 / 900)` параллелей при 100% успехе. Например, G7 ×10 требует G6 ≥12; G8 при таком G7 можно обеспечить максимум ×9. Программа рассчитывает все ступени от выбранного G7 или G8: **P** на общей панели или `WaterLineProgram plan g7 10`. Для G1–G6 это пока план, их управляющие модули будут добавлены позже.

**В GTNH 2.9 OC-компонент `gt_machine` не предоставляет метод установки максимальных параллелей.** Программа показывает расчёт и текущие параллели из сенсора G7, а максимальные значения нужно выставить в GUI каждой машины. План — минимум по объёму воды; добавь запас на неуспешные циклы и другие потребители.

## Проверка после запуска

- Фаза к середине цикла: «готово: всё залито точно».
- Большой шанс к концу цикла: **100%**. Это live-значение из сканера машины.
- Статистика: растёт «подтверждено машиной ✓».

| Симптом | Причина |
|---|---|
| `не найден компонент 'gt_machine'` | Adapter не касается контроллера |
| `в сети несколько 'gt_machine'` | не задан `machine` |
| сигнал всегда 0, каждый цикл льётся coolant | неверный `redstoneSide` или Redstone I/O не на лице хэтча |
| `на стороне 'to' нет хэтча` | неверный `to` |
| «запас ME-сети не виден» | нет Adapter у DI, или `me` указан неверно, или найдено несколько ME-компонентов |
| «нет поступления N с» | AE не доливает интерфейс: кончилась жидкость или интерфейс не в сети |
| шанс 0% после слива | в хэтч льёт кто-то ещё, или в интерфейсе не та жидкость или не тот тир SC |

## Тесты

`test/sim.lua` — модель G7 по исходнику GT плюс моки OC API. `test/g8_sim.lua` моделирует 120-секундный цикл G8: все 15 скрытых пар, стоимость повторных катализаторов в Molten Infinity, возврат лишних предметов, выход воды и барионной материи, пустые источники и тайм-аут. `test/bindings_test.lua` проверяет экран привязки для жидкости и предмета; `test/main_test.lua` — совместный запуск модулей; `test/parallel_test.lua` — расчёт воды. Запуск: `test/run.sh [циклов] [seed]`, `lua test/g8_sim.lua` и `lua test/*_test.lua` по одному файлу. Для конкретной пары и параллелей: `lua test/g8_sim.lua up down 4`.

`test/install_test.lua` — установщик на моках OpenOS: чистая установка, повтор, `--force-config`, 404, оборванная загрузка. Запуск: `texlua test/install_test.lua "$PWD" /tmp/inst`.
